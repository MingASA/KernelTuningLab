# Web v2 交付记录

Web v2 的包版本为 **1.1.0**，交付分支为 `feature/web-v2-workbench`，审核入口为 [PR #3](https://github.com/MingASA/KernelTuningLab/pull/3)。既有 main/v1.0.1 与历史标签保留；本轮不自动合并 main。人工上手仍待用户执行。

## 交付内容

- `ktlab serve`：loopback API、会话与 CSRF、静态上传检查、可信版本确认、原生 schema 预检与任务管理。
- 独立串行 Worker：持久状态、固定源码/插件/环境/GPU/预算、原 Runner、合作锁与资源门禁、取消、缓存恢复。
- React / TypeScript / ECharts：创建、工作区、队列、资产、分析、环境；SSE 重连补读、真实曲线、运行中参数和配置详情、成本与选择性导出。
- 迁移：停稳后的工作区归档、对象 SHA 与 SQLite 校验、移动恢复后的令牌轮换。测量仍由原生 SQLite 管理；控制库只存任务、事件和状态。
- 保留 `ktlab web` 的只读兼容。服务器不需要 Node 或 CDN；源码维护者构建前端。

部署见 [DEPLOYMENT](DEPLOYMENT.md)，操作见 [WEB](WEB.md)，个人练习见 [PERSONAL_HANDOFF](PERSONAL_HANDOFF.md)。

## 实际发现与修复

| 问题 | 根因与结果 |
|---|---|
| 服务 Python 与生产 Python minor 不同 | 环境发现曾带入服务端依赖目录。改为只传内容核验的 SDK 源码，生产解释器使用自己的依赖；H800 的服务与生产环境已实际分离执行 |
| 旧内核没有 Landlock | 不能把普通子进程当作隔离。实际 canary 通过的 Bubblewrap 承担命名空间和文件边界；上传 CPU 与 MoE 均在受限环境中执行 |
| GPU 设备 minor 查询失败 | 该驱动不接受 `nvidia-smi --query-gpu=minor_number`。改为按驱动 UUID/Device Minor 精确映射字符设备，不使用 ordinal 推断 |
| 受限编译找不到 ld | `/usr/bin/ld` 经 `/etc/alternatives/ld` 指向系统二进制，最初遗漏该只读链接目录。相同 C 程序旧配置链接失败，修复后编译和执行均成功；随后生产 GPU 验收通过 |
| 重启与恢复窗口 | 修复 SSE 关闭、持久执行交接与状态/事件原子写入。实际浏览器同一 EventSource 在 API 重启后重连并补齐观测 |
| 运行中只有配置 ID | 从原生 SQLite 按 record ID 定点读取配置摘要，沿用原生测量上下文分组；不扫描全部历史或复制原始样本到控制库 |
| 轮询重复携带完整环境身份 | 同一份 8 任务快照的 JSON 从 339683 bytes 降为 13203 bytes，减少 96.1%；完整冻结身份仍在详情中 |
| 停止命令过早返回 | 原 `worker --stop` 只发信号，归档随即被未释放租约拒绝。现在等待租约释放才返回成功，超时明确返回非零，未删除锁或绕过停稳检查 |

原失败、资源拒绝和各次尝试均保留在私有证据与远端目录中。没有降低正确性阈值、覆盖旧封存或关闭整个生产后端。

## CPU、浏览器与安装

干净 CPU/Web 环境的一轮全套为 **545 passed / 22 skipped**；后续设备绑定、实时配置、上下文与停机变更由最新定向回归及 CI 覆盖。工作台集成用例共 18 项，包含 ZIP 路径/链接/重复/膨胀、静态不执行、可信插件失败、身份篡改、认证/来源/CSRF、幂等、私有文件和凭据边界、Worker 崩溃接续、取消/缓存恢复、资源忙与归档恢复。

原 GPU 开发环境的两次全套运行出现子进程超时，首份日志保留；隔离复核通过，未增大测试超时。最新 CPU 3.10/3.12、原生优化器、Web 集成和前端重建由 CI 分别验收。

真实浏览器通过正常 SSH 转发连接 H800 的 loopback API，完成 **15 项检查**：上传、精确版本信任、异步预检、真实 CPU Runner、运行中曲线/参数/原始配置、同一 SSE 的 API 重启重连、无重复或缺失的观测、筛选、所选四文件下载、成员 SHA/SQLite 校验、窄屏和再次重启后的持久结果。

独立目录中的 wheel 安装完成 CPU 实验、scaffold/check 和核心加载检查；未导入 Torch/Triton。远端安装包的 **193 个包文件**与源码逐字节核对。前端实际截图见 [搜索](assets/web-v2-search.png)、[创建](assets/web-v2-create.png)、[窄屏](assets/web-v2-mobile.png)，均为真实远端 CPU 数据。CPU 验收夹具仅在真实提议阶段留出重连观察窗口，不用于算法性能结论。

最终部署与归档重启后另完成五项只读浏览器复核：工作区加载、既有 GPU 双方法曲线、图例开关、图内缩放和原生参数筛选，未新增实验。

## GPU 小预算验收

本轮仅验证 H800、Torch2.6/CUDA12.4、Triton3.2、vLLM0.8.5 兼容 MoE、FP16、固定 Shape 和明确的八点配置子集。计时为 CUDA Graph 完整调用，warmup=2、repetitions=3、batch=16；独立参考验证启用。

- Random、SMAC 各两次真实观测，四次均为物理搜索测量，另有一次独立验收；正确性通过，原始配置与真实曲线可查看。
- 取消/恢复采用现有 Random 的私有验收夹具，仅加入有界提议等待窗口。首条真实 GPU 观测后由浏览器取消，任务确认退出；同一冻结计划恢复后，一条缓存命中、一条新搜索测量，原记录身份保留且正确性通过。
- 显式恢复沿用原 Runner 规则，再进行独立验收；本项累计四条原生记录，不能把两轮验收误计为额外搜索。曲线时钟按当前尝试显示，旧尝试保留。
- 提交前遇到资源忙的拒绝被保留，未抢占他人进程，也未自动循环重试。每次实际执行均经过固定 UUID、连续资源检查和合作锁。

这不是全空间、全 dtype、全后端或新硬件验收。其它生产后端的已有 CLI 证据与支持边界见 [PRODUCTION_STABILITY](PRODUCTION_STABILITY.md)；登记独立环境后仍需定向 Web 路径验收。本轮未训练模型、调用付费模型 API 或重跑历史大矩阵。

## 迁移验收

在停止 API、等待 Worker 租约释放后，实际生成并恢复整个远端工作区：**4181 文件、1158 去重对象、6 个 SQLite**；逻辑文件共 89308544 bytes，归档 10747629 bytes。全部对象 SHA 与 SQLite 校验通过。

在新私有目录启动恢复后的 API，登录成功、令牌轮换，生产实验五条原记录 ID 与源工作区一致；恢复过程未执行 GPU 实验。原工作区、归档、恢复副本均保留，原服务随后重新启动。

这是当前机器的新目录迁移验收；没有声称跨 GPU 架构、驱动或 Python ABI 恢复通过。venv、驱动和原生组件仍按部署 profile 安装/重编译/重新验收。E 盘是离线资产库，不是在线写入位置；本轮没有要求服务器挂载 E 盘。

## 使用边界

当前为 Linux/WSL2 单用户 SSH 隧道部署、一个串行 Worker。Bubblewrap 默认隔离网络；Landlock 回退不具备相同的网络/PID 隔离。上传的 Python 必须可信，不承诺恶意代码的完整安全沙箱。API/SSH 凭据不会自动继承给 Worker；真实外部模型服务和额外推理资源未在本轮调用验收。

没有公网、多用户权限系统或分布式 GPU 调度器。没有真实轨迹、成本或 L3 部署身份的历史数据保持缺失，不补造。归档包含私有会话与机器资料，应私有保存；移动后轮换访问身份并重新登记环境。

结构化核验摘要与原证据 SHA 见 [ACCEPTANCE.json](../examples/web/ACCEPTANCE.json)。完整原始记录默认留在远端，仅明确选定的下载产物传到本机。
