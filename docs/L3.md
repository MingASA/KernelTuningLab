# L3: finite kernel variants

L3 chooses at most `K` configurations for a weighted shape distribution. It is an
offline planning component: observed performance is input, and the output is a
configuration set plus a shape assignment. It does not run a kernel or infer a
missing latency. The implementation uses only the Python standard library.

For normalized weights `w_i` and fully observed latencies `L_ij`, the objective is

```text
E(S) = sum_i w_i * min_{j in S} L_ij,       |S| <= K.
E_reference = sum_i w_i * min_{j in C} L_ij.
relative_loss = E(S) / E_reference - 1.
```

The loss is a ratio of weighted expected latencies. It is not the mean of
individual shape slowdown ratios. Zero-weight shapes do not constrain the
objective; a zero-weight shape may therefore have no dispatch assignment.

## Public API

```python
from kernel_tuning_lab.l3 import (
    PerformanceMatrix, SelectionResult, ShapeDispatcher,
    oracle, greedy, greedy_local_swap, bucket_baseline,
    evaluate_selection, k_loss_curve,
)

PerformanceMatrix(workload, configs, latencies_ms, provenance="unspecified")
PerformanceMatrix.from_records(workload, configs, records,
                               hardware_id=None, operator_id=None, provenance=None)
oracle(matrix, k, max_combinations=200_000)
greedy(matrix, k)
greedy_local_swap(matrix, k, max_passes=100)
bucket_baseline(matrix, k, bucket_dimension="M")
evaluate_selection(matrix, selected_indices, k=None)
k_loss_curve(matrix, ks=(1, 2, 4, 8, 16),
             methods=("greedy", "greedy_local_swap", "bucket"),
             max_combinations=200_000, bucket_dimension=None)
ShapeDispatcher.from_result(matrix, result, hardware=None, operator=None, space=None)
dispatcher.select_config(shape)
```

Optional arguments after `k` or `records` are keyword-only. Curves also accept
`"oracle"` as a method; an excessive exact request raises `OracleLimitError`.
Neither candidate columns nor assignment indices depend on configuration IDs:
indices always refer to the original matrix column order. Results serialize with
`result.to_dict()`; dispatch tables and matrices offer the same method.

`SelectionResult` exposes `method`, `k`, `selected_indices`, `configs`,
`assignment_indices`, `expected_latency_ms`, `conditional_latency_ms`, `coverage`,
`relative_loss`, `reference_latency_ms`, `provenance`, `exact`, and `metadata`.
`variant_count` may be smaller than `k`. `assignment_indices` contains a global
configuration column for every shape, or `None` when no selected cell is observed.
Provenance remains `mock`, `measured`, `imported`, or `unspecified` throughout.

## Missing observations and experiment context

The matrix has one row per workload shape and one column per candidate config.
Cells contain finite positive milliseconds or `None`. An unknown cell is never
replaced by a prediction, synthetic number, penalty, or fabricated measurement.
Prediction provenance is rejected. Manually supplied tables have unspecified
provenance until the caller identifies their source explicitly.

`from_records` groups one hardware/operator/source context, deduplicates record
IDs, and takes the median of all successful runtime samples per cell. Callers
must filter ambiguous contexts explicitly. Failure statuses and records explicitly
marked `metadata.correctness_verified=False` leave cells missing. Records with
`CORRECTNESS_UNKNOWN` are not successful. Source splits remain in matrix metadata;
callers choose the intended evaluation workload and supply only its authorized
records.

For a partial table, solvers first maximize the normalized weight of shapes with
an observed selected cell, then minimize the sum of their observed weighted
latencies. This explicit coverage objective avoids claiming unknown execution
costs. Selection `coverage` is observed shape weight, while matrix `coverage` is
the fraction of observed cells.

`conditional_latency_ms` is the weighted mean conditional on covered shapes.
`expected_latency_ms` is `None` unless every positive-weight shape is covered.
The unrestricted reference is `None` if any positive-weight shape has no observed
candidate. When each shape has some observations but other cells are missing,
`relative_loss` compares with the unrestricted **observed** reference;
`metadata.reference_scope="observed_cells_only"` identifies this limitation.
An exact result on an incomplete matrix certifies the stated observation and
coverage objective; it does not certify an optimum over unknown cells.

## Algorithms

The exact oracle enumerates all subsets of size `min(K, candidate_count)`.
Adding configurations cannot worsen the objective, so this also solves the
constraint `|S| <= K`. The number of subsets is checked before enumeration. An
explicit `max_combinations` limit prevents an unexpectedly large exponential
run. When the union of observed per-shape optimal configurations fits the budget,
the oracle returns immediately with an exact lower-bound certificate.

Greedy chooses the config giving the best resulting objective at each step and
stops when no single addition improves it. Greedy plus local swap repeatedly
takes the best improving replacement of one selected variant. Its metadata
reports convergence or exhaustion of `max_passes`; it claims no global optimality.
Ties use original column order for reproducibility; there is no random seed.

The bucket baseline sorts shapes by a requested dimension, divides them into
contiguous equally sized shape groups, and selects the best weighted observed
config for each group. Default `M` suits GEMM; non-GEMM workloads should call the
baseline with a present dimension such as `SeqLen`. Buckets select variants, then
the final finite-workload assignment uses the best observed selected config for
each shape. Bucket metadata describes the shape groups; it does not extrapolate
to new shapes. Heuristic quality, including bucket curves, need not improve
monotonically for every budget.

The curve helper automatically chooses `M` when available, otherwise the first
shared shape dimension in sorted order. Set `bucket_dimension` explicitly to
choose the dimension used by its bucket baseline.

The exact dispatcher stores a tuple of dimension/value pairs to config table.
Runtime work is dimension canonicalization and one dictionary lookup; it scans
neither performance columns nor kernel variants. Construction validates selected
membership, observed assignment cells, context identity, and the variant budget.
Providing `hardware`, `operator`, and `space` together additionally rechecks
operator-specific legality for every assignment. Unseen or unassigned shapes
raise `UnknownShapeError`, so a guessed config cannot silently become a verified
dispatch. Interval-based extrapolation and online measurement acquisition remain
future extensions.

## Reproducible small example

```python
from kernel_tuning_lab.models import ShapeSpec, KernelConfig, WorkloadDistribution
from kernel_tuning_lab.l3 import PerformanceMatrix, oracle, greedy, greedy_local_swap

shapes = tuple(ShapeSpec({"M": m}) for m in (1, 2, 3, 4))
configs = tuple(KernelConfig({"variant": x}) for x in ("general", "left", "right"))
workload = WorkloadDistribution(shapes, (1, 1, 1, 1))
table = PerformanceMatrix(workload, configs,
                          ((4, 1, 9), (4, 1, 9), (4, 9, 1), (4, 9, 1)),
                          provenance="mock")
assert greedy(table, 2).expected_latency_ms == 2.5
assert greedy_local_swap(table, 2).expected_latency_ms == 1.0
assert oracle(table, 2).expected_latency_ms == 1.0
```

These numbers are deliberately synthetic correctness checks, not benchmark
results. Run the independent weighted objective, exhaustive comparison, missing
cell, local swap, budget, provenance, and dispatcher checks with:

```bash
python3 -m unittest kernel_tuning_lab.l3.selfcheck
```
