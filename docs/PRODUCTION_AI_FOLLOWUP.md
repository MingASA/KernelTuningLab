# 生产配置空间 AI 补充实测

本轮先完成[生产平台审查](PRODUCTION_SUITE_AUDIT.md)，再按预先冻结的[协议](../examples/production_ai_study/protocol.json)完成7个新任务、40条方法轨迹，每条16次揭示，共640次测试观测。没有恢复旧的多seed大矩阵，也没有重测已有有效验收。结果仅描述这一组有限任务：**C 在两个 GemLite 任务中优于本次 Random 的最佳配置，B 没有显示一致收益；C1 在开发反馈后返回了与 C0 完全相同的程序。**

## 范围与实际执行

测试为FP16、seed41、每方法16次揭示和240秒墙钟上限。开发为不同Shape、seed23、每任务8次。计时为CUDA Graph，batch64、warmup5、15次重复；不要与CUDA Event、服务吞吐或完整调参总成本混用。任务、参数、Shape和验收点逐项固定在协议中。

| 设备/任务 | 比较方法 | 完整静态可行配置数 |
|---|---|---:|
| RTX4090 / GemLite W4 GEMM | Random、SMAC RF、KT DE、C0/C1 | 1500 |
| RTX4090 / GemLite W2 Split-K | 同上 | 4500 |
| H800 / FLUTE W3 | 上述方法及真实B | 24 |
| H800 / Flex dense、causal | 同上，每种mask独立 | 各36 |
| H800 / SGLang ragged paged decode | 同上 | 135 |
| H800 / vLLM MoE skewed | 同上 | 3200 |

所有方法访问相同权威空间，失败和精确缓存命中都消耗揭示预算。SMAC使用原生RF、initial_design_size4；KT使用原生DE、population8和持久callback，七任务均实际进入进化阶段。空间数是静态可行数，不能等同于全部配置已经编译或数值正确。

H800每个任务的所有方法共用Qwen3-1.7B权重常驻、合作静默的资源上下文；推理和候选准备/测速串行，关闭后登记生产者为0。4090未部署B，只比较其他五种方法。同一任务核对实际GPU UUID、软件/输入seed、计时和驻留上下文，不跨设备混排。

B采用显式完整静态grammar，真实模型logits选择，每任务16次、合计80次实际推理；没有512点池、启发式代选或参数补全。完整grammar是这个有限实验的变体，不是通用AI接口的强制要求。

C0/C1由已有Qwen3.8-27B分别真实生成一次，原文、可见输入、token和源码SHA保留。C0在7个开发任务揭示56点，51点参考验证通过、5点编译失败。C1只收到C0自己的每任务最佳2/最差1，共21行开发反馈及失败计数，未收到测试Shape或性能。两版代码逐字相同，SHA为`9553bf6057fafd737c76a925359644572f47ad0db4bcc470d0aa411e243072ee`；无人工修改。程序为通用邻域搜索与有界随机补全，见[完整源码](../examples/production_ai_study/results/generated_program.py)。C1复用相同源码的SDK契约结果，测试轨迹与C0的record IDs也完全一致，不能当作两种独立算法或迭代收益。

## 失败与运行时修正

640次揭示中，356次为新的实际评测尝试，284次为精确缓存命中；575次揭示参考验证通过、65次失败。新尝试中52次失败：47次编译失败、5次数值失败；按揭示计为56次编译失败、9次数值失败，差异来自缓存复用。通过的观测均要求真实GPU参考验证，未放宽容差。

数值失败包括GemLite W2 Split-K的4个SPLIT_K16配置，以及FLUTE的一个配置（Threads256、TileM32、Stages5、SMs_Multiple4）在测量后的复核失败。具体数值或输入完整性原因按原记录保留，未以猜测归因，也未依据测试结果更改空间或策略。它们不能支持“整个静态空间数值正确”的说法。审查中的FLUTE BF16默认/显式失败另见审查报告，不混作本轮FP16数据。

原始七批完成608次揭示；MoE的B、KT在15秒完整静态空间构造上限处停止，两者均为0观测，B尚未调用模型。只把这两项内层CPU构造时限调为120秒，外层240秒不变，在原冻结源码和同一物理GPU上补足32点。原数据库只读备份为精确上下文缓存；已完成的验收和原生默认遇缓存miss即拒绝准备，其他四个方法未重跑。原失败耗时30.115秒、原608点结果和补跑guard都独立保留。MoE静态检查逐候选调用组件身份路径，构造开销显著；未做进一步CPU性能归因或修改数值/搜索实现。

另一个开发期修正仅将同一FLUTE template4描述投影到已声明的可调键，解决构造前拒绝；原4090开发数据未重测。这两项[运行时修正](../examples/production_ai_study/runtime-amendments.json)均明确记录，补跑发生在测试已读之后，未修改提示、规则、解码、seed、空间或容差。

## 成本口径

| H800 B任务（每项16次） | 完整grammar构造 s | 纯生成合计 s | 提议合计 s | 试验墙钟 s |
|---|---:|---:|---:|---:|
| FLUTE | 0.069 | 8.798 | 11.026 | 12.975 |
| Flex dense | 0.037 | 9.304 | 13.618 | 17.429 |
| Flex causal | 0.036 | 8.887 | 12.499 | 15.554 |
| SGLang ragged | 0.132 | 10.174 | 12.625 | 18.905 |
| MoE补跑 | 48.313 | 14.817 | 65.871 | 78.433 |

各H800原始批次共同的1.7B模型加载为3.85–4.14秒一次，MoE补跑另加载4.26秒一次；不把每条响应重复携带的load字段累计为16次加载。现有`offload_wall_s`字段在本轮常驻模式下表示临时对象回收/同步时间，权重仍在GPU，不代表完整卸载搬移。

C0/C1纯生成分别49.064/64.590秒，各自27B加载16.256/17.565秒；客户端总耗时68.371/85.393秒。生成、开发评测和测试搜索分阶段记录，没有把生成成本藏入0秒。原生GemLite W4/W2内置调优墙钟6.919/6.287秒，各声明23个调优提议，但实际上游内部评测次数未导出；FLUTE默认内置调优8.463秒。编译/原生选择阶段、packing/准备和稳定执行分别保留，字段可能包含关系，不相加制造额外总成本。

各方法按冻结轮换顺序执行，共享编译和精确测量缓存。因此C0/C1的试验墙钟差异、缓存命中以及物理编译成本不能当作独立冷启动速度对照。完整成本、最优配置、原生实际配置及640步轨迹见[结果目录](../examples/production_ai_study/results/)。

## 可复核交付

GPU执行源码固定`f9b5b38`；开发4090/C0生成使用更早的`365428a`，仅FLUTE验收键绑定修正后的H800开发和全部测试使用`f9b5b38`。协议在生成前封存，程序/B策略在首次测试读取前冻结；初始与补跑证据SHA、分析与恢复helper SHA见[provenance.json](../examples/production_ai_study/results/provenance.json)。分析脚本只读核对记录ID、任务、seed、物理设备、计时与资源上下文。

两机新增原始证据已回传本地并恢复：H800617文件/26个SQLite，4090208文件/8个SQLite；共825文件/34个SQLite，SHA和quick_check全部通过。八份原始/补跑数据库导出与分析输入逐字段核对一致，80条B真实调用的配置逐一匹配揭示记录，两份C执行程序逐字匹配模型响应，见[核验摘要](../examples/production_ai_study/results/evidence_audit.json)。旧核心封存包和旧PAUSE_REQUESTED保持不变。公开结果去除主机、账户和设备UUID；原始资料只在本地私有忽略目录保存，异机备份无授权目标。

本轮没有真实API调用、额外卡、训练或新模型下载；A专门训练路线继续延期。独立推理设备模式仅CPU身份检查，未做双卡实测。FLUTE BF16、GemV/RevSplit及其他版本/架构的未覆盖范围仍按支持矩阵单列，不能从本轮结果推断通过。
