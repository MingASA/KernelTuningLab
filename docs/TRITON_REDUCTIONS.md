# Triton row reductions

`TritonSoftmaxAdapter` and `TritonLayerNormAdapter` implement real CUDA kernels behind the common runner contract. Their implementations are `triton_softmax` / `triton_layernorm`, with operator kinds `softmax` / `layernorm`. Importing their adapter module has no Torch/Triton import side effect; constructing an adapter checks the optional NVIDIA runtime. No GPU execution was available in the development environment: these implementations are not GPU-validated performance results.

Both kernels process contiguous two-dimensional input with `ShapeSpec({"M": rows, "N": columns})`. They normalize over the last axis (`axis=-1`; the equivalent two-dimensional `axis=1` is accepted). Supported input/output types are `float16`, `bfloat16`, and `float32`; accumulation and the reference calculation use float32. Softmax subtracts each row's maximum before exponentiation. LayerNorm computes population variance and implements non-affine forward normalization only: `affine=False`, `elementwise_affine=False`, and finite positive `eps` (default `1e-5`). Affine parameters and backward passes are unsupported and rejected.

Configuration keys are exactly `BLOCK_SIZE`, `num_warps`, and `num_stages`. Blocks must be powers of two covering `N`, with a maximum of 65536 elements. Warp counts are 4 or 8, stages are 1 or 2, and hardware thread limits are checked. Masked loads/stores handle row widths such as 193 and 1025. The vectors live primarily in registers: vector size is not treated as an actual shared-memory requirement. Triton compilation validates resources; reported compiled shared-memory usage is additionally checked against the physical hardware limit. Some stage choices may compile identically for these simple kernels; they remain ordinary compiler launch parameters, without introducing hardware-specific unsupported knobs.

Each run checks the requested hardware against the physical CUDA device, prepares seeded inputs, JIT-compiles separately from input preparation, compares against the float32 PyTorch reference cast to output dtype, performs warmups, and measures individual launches with CUDA events. Correctness inputs retain random rows; a constant first row is added for two or more rows, and a large-offset second row for three or more. Default absolute/relative tolerances are both `1e-5` for float32, `1e-3` for float16, and `1e-2` for bfloat16; callers can override them explicitly. Recorded correctness details include tolerances, normalization parameters, maximum error, and available compiled resource usage. Environment fingerprints hash the actual reduction kernel source.

The implementation uses the standard masked row-reduction approach described in the official [Triton fused softmax tutorial](https://triton-lang.org/main/getting-started/tutorials/02-fused-softmax.html) and [Triton layer normalization tutorial](https://triton-lang.org/main/getting-started/tutorials/05-layer-norm.html). These are implementation references, not measurements of this repository's kernels. This repository uses small independent forward-only kernels and the shared research runner rather than importing tutorial benchmark results.
